# 여행 영상 품질 경로

기존 영상의 식탁·야경·공항이 오래 이어지는 구성은 여행의 즐거움을 충분히 보여주지 못했다.
개선 방향은 원본의 여행 장소와 인물을 유지하면서 바닷바람, 이동, 작은 즐거움에 시간을 배정하는 것이다.
새 장면을 먼저 검사하고, 좋은 구간만 골라 정확히 30초로 편집한다.

## 실제 생성과 출력 해상도

`build_ltx_workflow`의 샘플러를 공식 FLF 예제에 맞는
`SamplerEulerAncestral(eta=0.0, s_noise=1.0)`으로 수정했다.
기존 CFG++ ancestral 설정과 달리 추가 ancestral noise를 주입하지 않는다.
기존 기본 해상도와 디코더 설정은 이 수정만으로 바뀌지 않는다.

`build_ltx_quality_workflow`는 정확히 두 개의 장면 가이드를 받는 별도 경로다.

- 실제 확산 해상도 1024×576, 24fps, 30초 요청은 721프레임.
- 가이드 리사이즈 후 `LTXVPreprocess(img_compression=25)` 적용.
- 공간 타일768/겹침64, 시간 타일256/겹침32로 VAE 디코딩.
- 한 장면에 샘플러 한 번. 서로 다른 장소를 한 장면 안에서 변형하지 않는다.
- 원본이 한 장이면 동일 사진을 첫·끝 가이드로 사용할 수 있다. 서로 다른 두 장으로 기록하지 않는다.

이 경로는 공식 2단계 latent upscaler/refinement 구현이 아니다.
30초는 자체 GPU 시험 길이이며 실제 메모리·시간·움직임 검증이 필요하다.
소스가 1024×576이고 최종 파일이 1920×1080이면 후자는 확대 출력이다.
코드·스키마 검증 성공은 실제 화질 개선이나 인물 보존 성공을 뜻하지 않는다.
고정 출처와 설정은 `LTX_QUALITY_PROVENANCE`에 기록한다.

## 컷 편집과 음악

`render_premium_film`은 검토한 `FilmTake` 목록을 받아 원래 속도로 연결한다.
기본 출력은 30초·24fps·1920×1080이다. 입력 FPS가 다르면 조용히 재생 속도를 바꾸지 않고 거부한다.
사진 정지 장면이나 프레임 보간을 추가하지 않는다. 검은 시작 화면을 넣지 않고,
장면 사이에는 컷을 사용한다. 한글 타이틀은 시작과 끝에만 넣는다.

음악은 실측 후 두 번 처리해 -16 LUFS, true peak -1dBTP를 목표로 한다.
출력 후 오디오 스트림·시간·실제 음량을 검사하고, 곡의 분위기는 청취로 판단해야 한다.
ACE-Step 경로는 30초·120BPM·D장조의 밝은 여행 음악 후보를 생성한다.
`ace_music.py`는 영상용 `ComfyUI.wait()`와 다른 오디오 history 출력을 처리한다.
작곡 결과 역시 자동으로 품질 승인하지 않는다.

## 선택·검수 기준

OpenCV는 원본의 흐림·노출·중복 후보를 추린다. 전체 사진의 Laplacian 분산이 높아도
관심 피사체만 흐릴 수 있으므로 전경·인물·음식의 상태는 별도로 확인한다.
모델은 원본을 바탕으로 새 프레임을 생성하므로 난간·나뭇가지·손·차체 변형과
새 인물, 얼굴 변화, 합성된 사진 액자 등이 없는지 실제 움직임을 검사한다.
소스 실패 구간을 제목·확대·색보정으로 가린 결과를 품질 통과로 기록하지 않는다.

현재 새 경로는 Python 라이브러리와 이번 로컬 제작 도구에서 사용한다.
기존 영상 요청 API에 새로운 사용자 선택 UI나 자동 ACE 음악 생성이 연결되었다는 뜻은 아니다.
