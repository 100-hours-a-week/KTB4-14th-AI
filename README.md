# AUDIGO AI V1 Development

AUDIGO V1의 AI 기능을 개발하고 검증하기 위한 레포지토리입니다.

현재 개발은 `development/` 폴더를 기준으로 진행하며, 세부적인 구현 기준과 실행 방법은 [V1 개발 가이드](V1%20개발%20가이드.md)를 참고합니다.

---

## 개발 범위

V1에서는 AUDIGO 서비스에서 사용하는 AI 기능을 구현하고, 실제 사용 가능한 수준까지 검증하는 것을 목표로 합니다.

주요 개발 범위는 다음과 같습니다.

* AI API 구현
* 입력 데이터 검증 및 전처리
* 프롬프트 설계 및 관리
* 모델 호출 로직 구현
* 외부 데이터 활용
* AI 응답 가공 및 정규화
* 예외 처리
* 로그 및 테스트 코드 작성
* AI 결과 품질 검증

---

## API 기준

AI API의 URL, Request, Response 구조는 Google Sheets의 `[AUDIGO] AI 인공지능` 탭을 기준으로 관리합니다.

해당 문서에서는 다음 항목을 확인합니다.

* API URL
* HTTP Method
* Request 형식
* Response 형식
* Status Code
* 필수 및 선택 데이터

API 명세와 실제 AI 처리 로직은 분리해서 관리합니다.

따라서 API 형식은 유지하면서도 프롬프트, 모델, 데이터 처리 방식 등 내부 AI 로직은 필요에 따라 개선할 수 있도록 구성합니다.

---

## AI 처리 흐름

기본적인 AI 처리 흐름은 다음과 같습니다.

```text
Request
  ↓
Input Validation
  ↓
Preprocessing
  ↓
Prompt / AI Logic
  ↓
Model / External Data
  ↓
Result Validation
  ↓
Postprocessing
  ↓
Response
```

AI 요청이 들어오면 입력값을 먼저 검증하고, 기능에 필요한 형태로 데이터를 가공한 뒤 AI 로직을 실행합니다.

모델의 결과는 그대로 사용하지 않고, 결과 검증과 후처리를 거쳐 서비스에서 사용할 수 있는 형태로 정리합니다.

---

## 입력 데이터 처리

AI 처리 전에 입력값이 필요한 조건을 만족하는지 확인합니다.

주요 검증 항목은 다음과 같습니다.

* 필수 입력값 존재 여부
* 데이터 타입
* 입력값 범위
* 잘못된 값 또는 비정상적인 요청
* AI 처리에 필요한 정보 존재 여부

잘못된 입력은 모델 호출 전에 처리하여 불필요한 호출을 줄이고, 정상적인 요청만 실제 AI 처리 단계로 전달합니다.

---

## Prompt 및 AI Logic

AI 기능별로 필요한 프롬프트와 처리 로직을 분리해서 관리합니다.

프롬프트에는 단순한 생성 명령뿐 아니라 다음과 같은 기준을 포함할 수 있습니다.

* 출력 형식
* 생성 규칙
* 필수 포함 항목
* 제외 조건
* 데이터 우선순위
* 결과 검증 기준

프롬프트 변경이 API 구조나 다른 기능에 영향을 주지 않도록 기능 단위로 관리하는 것을 기본 원칙으로 합니다.

---

## 모델 처리

AI 기능에 필요한 모델 호출 로직은 기능별 요구사항에 맞게 구성합니다.

모델 선택 시에는 단순히 성능이 높은 모델을 사용하는 것이 아니라 다음 요소를 함께 고려합니다.

* 생성 품질
* 응답 속도
* 비용
* 출력 안정성
* 구조화된 응답 가능 여부
* 프롬프트 제어 가능성

필요한 경우 동일한 기능에 대해 여러 모델이나 프롬프트를 비교하여 결과 품질을 검증합니다.

---

## 외부 데이터 활용

AI 결과의 정확도를 높이기 위해 필요한 경우 외부 데이터를 함께 활용합니다.

AI가 알고 있는 정보만으로 결과를 생성하지 않고, 실제 서비스에서 필요한 최신 정보나 구체적인 데이터는 별도의 데이터 소스를 통해 보완할 수 있도록 구성합니다.

외부 데이터를 사용하는 경우 다음 항목을 확인합니다.

* 데이터 유효성
* 최신성
* 누락 여부
* 중복 데이터
* AI 입력에 적합한 형태인지 여부

---

## 결과 검증

AI가 생성한 결과를 그대로 최종 결과로 사용하지 않고, 필요한 검증 과정을 거칩니다.

주요 검증 항목은 다음과 같습니다.

* 필수 데이터 누락 여부
* 예상한 응답 형식 여부
* 중복 결과 여부
* 비정상적인 값 존재 여부
* 요청 조건 충족 여부
* 서비스에서 실제 사용할 수 있는 결과인지 여부

검증에 실패한 결과는 후처리하거나 필요한 경우 재생성하도록 구성할 수 있습니다.

---

## Response 처리

AI 처리 결과는 API에서 정의한 Response 구조에 맞게 가공합니다.

모델의 원본 출력과 최종 Response를 분리함으로써 모델이나 프롬프트가 변경되더라도 API 구조가 불필요하게 변경되지 않도록 합니다.

---

## 예외 처리

AI 기능에서는 일반적인 API 오류 외에도 모델 및 외부 데이터 처리 과정에서 발생할 수 있는 오류를 고려합니다.

주요 예외 상황은 다음과 같습니다.

* 잘못된 Request
* 모델 호출 실패
* 외부 데이터 조회 실패
* AI 응답 생성 실패
* 예상한 형식과 다른 응답
* 결과 검증 실패
* 처리 시간 초과

오류가 발생한 경우 원인을 로그로 확인할 수 있도록 하고, 동일한 문제가 반복되는지 확인할 수 있는 구조를 유지합니다.

---

## 로그

AI 기능의 동작 상태를 확인하기 위해 주요 처리 단계에 로그를 남깁니다.

필요한 로그 범위는 다음과 같습니다.

* 요청 처리 시작 및 종료
* 입력값 검증 실패
* 모델 호출 성공 및 실패
* 외부 데이터 조회 성공 및 실패
* 응답 파싱 실패
* 결과 검증 실패
* 예외 발생 위치

민감한 정보나 불필요한 전체 Request / Response가 그대로 로그에 남지 않도록 주의합니다.

---

## 테스트

AI 기능은 단순히 API가 정상 호출되는지만 확인하지 않고, 실제 생성 결과의 품질까지 함께 검증합니다.

테스트 범위는 다음과 같습니다.

* 정상 입력
* 잘못된 입력
* 필수 값 누락
* 경계값
* 모델 응답 실패
* 비정상적인 AI 응답
* 외부 데이터 조회 실패
* 결과 형식 검증
* 실제 생성 결과 품질 확인

AI 기능 특성상 동일한 입력에서도 결과가 달라질 수 있으므로, 단순 문자열 일치보다는 필요한 조건을 만족하는지를 기준으로 검증합니다.

## 개발 원칙

V1 AI 개발에서는 다음 기준을 유지합니다.

1. API 구조와 AI 내부 로직을 분리한다.
2. 모델의 원본 출력을 그대로 사용하지 않는다.
3. 입력 검증 후 필요한 경우에만 모델을 호출한다.
4. AI 결과에 대한 검증 단계를 둔다.
5. 프롬프트와 모델 로직을 기능 단위로 관리한다.
6. 모델 변경이 전체 구조에 영향을 주지 않도록 구성한다.
7. 생성 결과의 품질과 안정성을 함께 검증한다.
